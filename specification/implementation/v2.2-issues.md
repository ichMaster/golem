# v2.2 — Issues

Issues for phase **v2.2 — The text game screen** (version **v2 — Prototype: a text game screen, Lua runs and
the program swap**), derived from the Tasks and DoD in [ROADMAP.md](../ROADMAP.md) §v2.2 and the contracts in
[ARCHITECTURE.md](../ARCHITECTURE.md). This file covers one phase; ids continue from the previous phase
(GOLEM-013 → **GOLEM-014…017**).

The phase puts a plain text page in front of the v2.1 human game. The server serves the page from the
package, and the page plays over `/ws` and reconnects by itself. The game is saved to a file so that it
survives a server restart. The designed "Clay and stone" screen (v3.1–v3.3) replaces the page later. It keeps
the page's serving, socket and reconnect.

**Reconciled with the code (v2.1.0, then the docs up to commit 869c499):**
- `golem/server/app.py`: `create_app(settings)` checks the levels, sets up logging, installs the error
  handlers (every error is `{"error", "detail"}`; `404 not_found` from `starlette.exceptions.HTTPException`),
  `GET /api/levels` and `install_ws(app, levels_dir, port)`. No route serves a page yet.
- `golem/server/config.py`: `Settings(host, port, levels_dir, log_dir)`, a frozen dataclass.
  - The tests build it **positionally** (`tests/test_server_levels.py`, `tests/test_server_ws.py`,
    `tests/test_server_app.py::settings_for`), so a new field needs a default.
  - `log_dir` is `data/logs` under the working directory; `GOLEM_DATA_DIR` arrives only in v5.2.
- `golem/server/ws.py`:
  - `Game(level, budget, world)`, frozen;
  - `handle(text, game, levels_dir) -> (reply, game)`, a pure function;
  - `state_message(game)`;
  - the game lives on `app.state.game`, one per server, in memory only;
  - a client that connects gets the current `state` first, when a game is loaded;
  - the Origin allowlist is `http://127.0.0.1|localhost|[::1]:<port>`, so a page served by this server is
    accepted as is.
- `golem/core/world.py`: `to_json(world)` and `from_json(data, level)` (save and restore, v1.3). The latter
  raises `ValueError` naming the field when the save does not fit the level.
- `golem/screen/` holds only `art/golem-art.js` and `art/golem-fx.js`. They were committed in e172718 for
  v3.2 and v3.3, and neither references an external URL. There is no `golem/screen/__init__.py`.
- [v2-owner-test.md](v2-owner-test.md): hands-on testing of the human game was **moved to v2.2**. It is
  GOLEM-017.
- [v2.1-code-review.md](v2.1-code-review.md): the deferred #3 (`Host` check) belongs to v5.1, and #4 to the
  backlog. Neither is in this phase.

**Drift and the owner's decision (2026-11-20):**
- **The drift:** the ROADMAP DoD says that after a **server restart** the page "continues the game where it
  was". The v2.1 server keeps the game in memory only, so a restart loses it.
- **The decision:** the owner chose to **save the game to a file**. The server writes
  `data/human-game.json` after every change and restores it at start (GOLEM-016).
- **The documents it changes:** ROADMAP §v2.2's Tasks and Tests, and ARCHITECTURE's WebSocket contract, its
  data files table and §Error handling. They are updated in GOLEM-016.

### GOLEM-014 — Serve the screen from the package: `GET /` and `/screen/…`

**Description:**
The server serves the game screen. `GET /` answers the page, and `/screen/…` serves the files under
`golem/screen/` with their content types and nothing outside that directory. Touches `golem/server/app.py`,
a first `golem/screen/index.html` (filled in by GOLEM-015) and a new `tests/test_server_screen.py`.

**What needs to be done:**
- Find the screen directory through the package, not the working directory: `Path(golem.__file__).parent /
  "screen"` or `importlib.resources`. The server must serve the same files when it is started from another
  directory.
- `GET /` answers `golem/screen/index.html` as `text/html`.
- `/screen/…` serves the files under `golem/screen/`, e.g. with Starlette's `StaticFiles` mounted on
  `/screen`, and no directory listing. Use the standard content types: `.html` as `text/html`, `.js` as
  `text/javascript`, `.css` as `text/css`.
- A path outside `golem/screen/`, raw or percent-encoded (`..`, `%2e%2e`, `..%2f`), a missing file and the
  bare directory all answer `404` with the usual `{"error": "not_found", "detail": …}` body. Check that the
  app's error handler covers the mounted files too.
- `GET /api/levels` and `/ws` are unchanged.
- A first `index.html`: a valid HTML5 page with the title "Golem" and a `<script src="/screen/screen.js">`,
  plus an empty `screen.js`, so that every reference resolves. GOLEM-015 fills both in.

**Dependencies:** None

**Expected result:**
`curl http://127.0.0.1:8700/` returns the page, `/screen/screen.js` returns the script, and no path reaches a
file outside `golem/screen/`.

**Acceptance criteria:**

### GOLEM-015 — The text page: map, status, level buttons, keys and reconnect

**Description:**
The prototype's screen: a plain page that plays the human game over `/ws` and draws every state as text.
Touches `golem/screen/index.html`, `golem/screen/screen.js` and `tests/test_server_screen.py`.

**What needs to be done:**
- **Plain HTML and JavaScript:** no framework, no build step, no CDN, no canvas, no animation, and no rules
  in JavaScript. The page never decides whether a move is legal: it sends the key and draws the state that
  comes back (ARCHITECTURE §The game screen).
- **`index.html`** shows:
  - the map in a `<pre>`, exactly as the state's `map`, one row per line, in a monospace font;
  - the level id and `steps / budget`;
  - the status with its reason: `playing`, `solved in N steps`, `lost — out of steps` (reason `steps`) or
    `lost — a box is stuck in a corner` (reason `deadlock`);
  - one button per training level from `GET /api/levels`, labelled with the level's name and its step budget
    and grouped by tier, with the current level marked. A button sends `{"type": "load", "level": id}`;
  - the key hints: `← ↑ → ↓ move · R restart`;
  - an error line that shows the `detail` of an `error` reply and clears on the next state;
  - the connection line: `connected` or `reconnecting…`;
  - before any level is loaded, a short prompt to pick a level.
- **Keys** (`keydown` on the document):
  - `ArrowUp`, `ArrowRight`, `ArrowDown` and `ArrowLeft` send `move` with `N`, `E`, `S` and `W`, with
    `preventDefault` so the page does not scroll;
  - `r` or `R` sends `{"type": "restart"}`;
  - a key with Ctrl, Meta or Alt is ignored, so `Cmd+R` still reloads the page;
  - every key is ignored while the socket is not open, and nothing is queued.
- **The socket:**
  - The URL comes from the page's own location, e.g. `new URL("/ws", location.href)` with the protocol
    switched to `ws:`. No host or port is written into the code.
  - The page connects when it opens and draws every `state` it receives.
  - On `close` it shows `reconnecting…`, dims the map and retries after 0.5, 1, 2 and 4 s, then every 5 s.
    The schedule resets after a successful open.
  - After a reconnect the server sends the current state when it holds a game (GOLEM-016 keeps it across
    a restart), and the page draws it.
  - If the level list failed to load, the page fetches it again after a reconnect.
- Keep `screen.js` small and readable, with the socket, the keys and the drawing in separate functions. v3.2
  replaces the drawing and keeps the socket and the reconnect.

**Dependencies:** GOLEM-014

**Expected result:**
The owner opens `http://127.0.0.1:8700/`, picks a level and plays it with the arrows and `R`. The page shows
the map, the steps, the result and errors, and it survives a dropped connection.

**Acceptance criteria:**
- [ ] The page shows every element listed above. The keys and the reconnect schedule are as specified.
- [ ] **Tests** (`tests/test_server_screen.py`):
  - `index.html` references only files under `/screen/` that exist and are served, and loads no script or
    stylesheet from anywhere else;
  - `screen.js` writes no host, port or scheme into the code (the no-external-URL test from GOLEM-014 covers
    `ws://`);
  - the `/ws` messages that the page sends (`load`, `move` with `N`/`E`/`S`/`W`, `restart`) are the
    contract's messages. A `TestClient` WebSocket plays `training/tier1/t1-01`'s recorded solution with
    exactly these messages and ends `solved`.
- [ ] **Gates:** lint and tests green.
- [ ] **Manual (owner), Claude may run it:** with `uv run golem-server` running, `curl -s
      http://127.0.0.1:8700/` returns the page, and a `websockets` script that sends the page's messages
      plays a level to `solved`. The browser checks are GOLEM-017.

### GOLEM-016 — The human game survives a server restart: `data/human-game.json`

**Description:**
The server saves the human game to a file after every change and restores it when it starts, so a page that
reconnects after a restart finds the game where it was. This is the owner's decision of 2026-11-20. Touches
`golem/server/ws.py`, `golem/server/config.py`, `golem/server/app.py`, `tests/test_server_ws.py`,
`specification/ARCHITECTURE.md` and `specification/ROADMAP.md`.

**What needs to be done:**
- **The file:** `data/human-game.json` under the working directory, like the log, until `GOLEM_DATA_DIR`
  arrives in v5.2.
  - Add a `game_file: Path | None = None` field to `Settings`. `load_settings` sets it to
    `Path("data/human-game.json").resolve()`, and `None` turns saving off. Existing tests that build
    `Settings` positionally keep working and save nothing.
- **The content:** `{"world": to_json(world)}`. `to_json` already carries the level id, and nothing else is
  needed: the budget is read again from `budgets.toml` on restore. Keys sorted, UTF-8.
- **Save** after every message that changes the game (`load`, `move`, `restart`).
  - The write is atomic: a temporary file in the same directory, then `os.replace`.
  - A failed write is logged and the game goes on in memory; the client still gets its `state`.
  - Keep `handle` pure: the route saves the game when `handle` returns a different one.
- **Restore** in `install_ws` (or `create_app`) when the file exists:
  - The level id must be in `list_levels("training", levels_dir)`. A hidden or unknown id is refused, like
    `load`.
  - The level, the budget and `from_json(data["world"], level)` must all load.
  - The restored game is `Game(level, budget_for(...), world)`, and the next connection receives its
    `state`.
  - Any failure (not JSON, a missing key, a refused id, a `ValueError` from `from_json`, a broken level) is
    logged as a warning without the file's contents or any level text, and the server starts with no game.
    The file is left as it is; the next `load` overwrites it.
- **Docs, in the same commit:**
  - ARCHITECTURE §HTTP API, the WebSocket bullet "One game, kept in the server": the game is saved to
    `data/human-game.json` after every change and restored at start, so a page that reconnects after a
    server restart finds it where it was. A save that does not restore is ignored with a warning.
  - ARCHITECTURE §Data and state files: a new row, `data/human-game.json` | the server (v2.2) | the human
    game: the saved world of the current training level.
  - ARCHITECTURE §Error handling and resilience: the WebSocket line says that the game survives a restart.
  - ROADMAP §v2.2: a task bullet, **The game survives a restart**, and a test bullet for it.

**Dependencies:** None

**Expected result:**
Load a level, make some moves, restart `golem-server`: a client that connects receives the same state
(level, map, steps, status) as before the restart.

**Acceptance criteria:**
- [ ] **Tests** (`tests/test_server_ws.py`, `TestClient`, `game_file` in `tmp_path`):
  - **restart:** app A loads `t1-02` and makes three moves. App B is created with the same settings, and a
    new connection to it receives a state equal to A's last state. A `move` on B goes on from there.
  - **solved and lost games** restore with their status and reason.
  - **`restart` and `load`** overwrite the save; after a new `load`, B restores the new level.
  - **a broken save** starts with no game, the connection receives nothing first, and the server still
    serves `load`. Broken means: not JSON, not an object, a missing `world`, a world that does not fit the
    level, an unknown id, and a hidden id from the fixture hidden root. No line of the fixture hidden map
    appears in the log.
  - **saving off:** with `game_file=None` nothing is written.
  - **the write is atomic:** no temporary file is left after a save.
- [ ] **Determinism:** the saved file for the same messages is byte-identical on two fresh apps.
- [ ] **Contract:** the WebSocket contract ("One game, kept in the server": saved and restored), the data
      files table and §Error handling are updated in ARCHITECTURE.md, and ROADMAP §v2.2 in the same commit.
      They are pinned by the restart tests above.
- [ ] **Gates:** lint and tests green.
- [ ] **Manual (owner), Claude may run it:** with `uv run golem-server`, a `websockets` script loads a level
      and moves. After the server is restarted, a new connection receives the same state.
