## Detailed Results

### GOLEM-014: Serve the screen from the package
**Status:** completed · **Commit:** 51def7e · **GitHub:** #14
**Gates:** [x] lint · [x] tests (362) · [ ] determinism (n/a)
- `GET`/`HEAD /` answers `golem/screen/index.html`. `/screen` mounts `StaticFiles` on the package's
  `golem/screen/`.
- HEAD was added after `curl -sI /` answered 405: FastAPI's `@app.get` does not answer HEAD.
- `/screen` (without the slash) redirects to `/screen/`, which answers 404. The test follows the redirect.
- Percent-encoded traversal reaches the app with `..` in the decoded path, so the tests exercise the
  `StaticFiles` guard itself. httpx normalises the raw `..` form before sending, and that form answers 404
  as well.
- The wheel built by `uv build` contains `golem/screen/`.

**Manual (Claude may run it):** `curl -sI /` → `200 text/html`, `curl -sI /screen/screen.js` →
`200 text/javascript`; `--path-as-is /screen/../server/app.py` → 404 JSON.

### GOLEM-015: The text page
**Status:** completed · **Commit:** 657ca4a · **GitHub:** #15
**Gates:** [x] lint · [x] tests (366) · [ ] determinism (n/a)
- `index.html` (inline style) and `screen.js`: the map in a `<pre>`, level, `steps / budget`, status with its
  reason, the error line, key hints, the connection line, and level buttons grouped by tier with the current
  one marked.
- The socket URL is built from `location`. The page reconnects after 0.5, 1, 2 and 4 s, then every 5 s, and
  the schedule resets after an open.
- Keys pressed while the socket is closed are dropped. Keys with Ctrl, Meta or Alt are ignored.
- After an open the page shows the empty prompt until the server's state arrives, so a server with no game is
  never drawn with an old map.
- Behaviour was checked with `node --check` and a throwaway node harness with a fake DOM and WebSocket:
  23 checks, not committed, because the gates stay Python-only.

**Manual (Claude may run it):** `curl /` returns the page. A `websockets` client sends the page's `Origin`
and messages and plays t1-01 to `solved`.

### GOLEM-016: The human game survives a server restart
**Status:** completed · **Commit:** 8edc350 · **GitHub:** #16
**Gates:** [x] lint · [x] tests (381) · [x] determinism (the save is byte-identical for the same messages)
- The owner's decision of 2026-11-20 (see [v2.2-issues.md](v2.2-issues.md)): save the game to
  `data/human-game.json` after every change and restore it at start.
- `Settings.game_file` defaults to `None`, which turns saving off, so the existing tests save nothing.
  `load_settings` sets the real path.
- A save that does not restore is logged with a fixed reason and never echoes the file.

**Manual (Claude may run it):** run from a scratch directory, the server loaded t1-02 and took three moves,
was killed and started again, and a new connection received the same state.
