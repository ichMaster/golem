## Findings

### 1. 🟠 `/ws` accepts any web page's connection — FIX NOW

**Where:** `golem/server/ws.py:107` (`human_game` accepts every handshake).

**What:**
- Browsers don't apply the same-origin rule to WebSockets. Any page the owner opens can call
  `new WebSocket("ws://127.0.0.1:8700/ws")`, and the browser sends the page's own `Origin` with the
  handshake. The server never looks at it.
- Binding to `127.0.0.1` keeps other machines out (ARCHITECTURE §Security), but not other web pages on
  the owner's machine.

**Failure scenario:** a `TestClient` connection with `Origin: https://evil.example` loads
`training/tier1/t1-01` and gets its state.
- Today such a page can read training maps (public anyway) and change the owner's human game.
- From v5.3 the same server drives replays, and every later route inherits the habit of trusting any
  caller.

**Fix:**
- Accept a handshake only without an `Origin` header (a non-browser client) or with the server's own
  origin: `http://127.0.0.1:<port>`, `http://localhost:<port>` or `http://[::1]:<port>`.
- Close any other handshake with code 1008 (policy violation) before accepting it.
- ARCHITECTURE: the WebSocket contract and the Security table.
- Regression test: a foreign origin refused, the server's own origins and no origin accepted.

### 2. 🟡 `.env` is searched up the parent directories — FIX NOW

**Where:** `golem/server/app.py:131` (`load_dotenv(find_dotenv(usecwd=True))`).

**What:** `find_dotenv` walks from the working directory up to the filesystem root and loads the first
`.env` it finds. ARCHITECTURE.md (GOLEM-011) says `golem-server` reads `.env` from its working directory.

**Failure scenario:** started from a checkout without its own `.env`, the server loads, say,
`~/development/.env`. Its variables (another project's settings, an API key) land in the server's
environment, and a `GOLEM_*` value there silently changes the configuration.

**Fix:** load exactly `<cwd>/.env`, if it exists. Regression test: a parent directory's `.env` with
`GOLEM_PORT=9999` is not read.

### 3. 🟡 No `Host` check on HTTP routes — DEFER → v5.1

**Where:** `golem/server/app.py:40`.

**What:** a page served from a domain the attacker controls can rebind that domain to `127.0.0.1`. The
browser then lets the page read this server's HTTP responses (DNS rebinding).
- Today the only route is `GET /api/levels`: public training metadata.
- From v5.1, `GET /api/runs/current` returns snapshots and reports of the agent's runs.

**Home:** v5.1, when the run routes arrive. Accept only `Host` values `127.0.0.1`, `localhost` or `[::1]`
with the server's port, for example with `TrustedHostMiddleware`. The tests' `TestClient` would then need
a matching `base_url`.

### 4. 🟡 An unexpected exception in the WebSocket handler — DEFER → backlog

**Where:** `golem/server/ws.py:113`.

**What:** `handle` catches every error a message can cause; no input found in review raises. If a future
bug raises inside it, Starlette closes the connection with code 1011. The client gets no `error` reply,
and the traceback goes to uvicorn's console only, not to `server.log`. The server itself keeps running.

**Home:** backlog. When the page reconnects (v2.2), a closed connection costs nothing. Revisit if the
WebSocket gains more message types (v5.3).

## What's solid

- **Hidden levels:** `/api/levels` lists the training set only. `load` refuses hidden, unknown and
  non-string ids with one identical reply. Tests run both routes against a root that holds the fixture
  hidden level and look for its id and every map line in the responses.
- **One core:** the WebSocket layer calls `move`, `new_world` and `render`. Even direction validation
  comes from the core's `ValueError`.
- **The protocol:**
  - `handle` is a plain function, so a bad message provably leaves the game unchanged;
  - after every error case, the same connection keeps working;
  - details never echo the message.
- **Configuration:**
  - a non-loopback host is refused before uvicorn is ever called;
  - a missing training set or a broken `budgets.toml` stops the start (v1 code review #4);
  - a non-string level id is "unknown level" (v1 code review #7).
- **Live checks:** `golem-server` with `curl` and with a real `websockets` client. They caught the missing
  `websockets` dependency that `TestClient` hides.

## Fixes applied

Both fixes are on `v2-dev`. After the last one: lint clean, 337 tests green, and CI green on 68ef7bf and
ec4696c.

### #1 — `/ws` accepts only the server's own page (68ef7bf)

- **Change:** `install_ws(app, levels_dir, port)` reads the handshake's `Origin`. It accepts no `Origin`,
  or `http://127.0.0.1:<port>`, `http://localhost:<port>` or `http://[::1]:<port>`. Anything else is
  logged (with `%r`) and closed with code 1008 before `accept`.
- **Regression tests:**
  - `tests/test_server_ws.py::test_a_foreign_origin_is_refused_before_the_handshake`: a foreign site,
    `null`, another port, a look-alike host, `https` on the right port;
  - `test_the_servers_own_page_may_connect`: the three own origins.
- **Verification:** against the old code, all five refusal cases fail. With the fix, 335 tests passed.

### #2 — `.env` from the working directory only (ec4696c)

- **Change:** `main()` loads `Path.cwd() / ".env"` when that file exists, instead of
  `find_dotenv(usecwd=True)`, which walks up to the root.
- **Regression tests:**
  - `tests/test_server_app.py::test_a_parent_directorys_env_is_not_read`: a parent's `GOLEM_PORT=9999`
    is ignored;
  - `test_the_working_directorys_env_is_read`: `GOLEM_PORT=8801` is used.

  Both run `main()` on a private copy of `os.environ`, with uvicorn replaced.
- **Verification:** against the old code, the parent-directory test fails. With the fix, 337 tests passed.

## Architecture impact

- **WebSocket contract:** a new **Origin** rule in ARCHITECTURE §HTTP API. Browser clients must be the
  server's own page (`http://127.0.0.1|localhost|[::1]:<port>`). Non-browser clients send no `Origin` and
  are accepted. The v2.2 page is served by this server from the same origin, so it is accepted as is.
- **Security table:** a new row, "A web page open in the owner's browser uses the server". It covers the
  Origin rule and the absence of CORS headers, and names the `Host` check that v5.1 owes (#3).
