## Design notes

These are the spike's answers ([v2.3-lupa-spike.md](v2.3-lupa-spike.md)) and what the build added.

**Design decisions:**
- **Coroutines are driven from Lua.** A driver chunk in the runtime's globals resumes the coroutine. lupa's
  own coroutine wrapper is not used, because the count hook and the sentinel check must live in Lua.
  Python cannot compare Lua tables by identity: two proxies of one table are neither `is` nor `==`.
- **Text is cleaned in Lua.** The runtime keeps lupa's UTF-8 encoding.
  - With `encoding=None`, a Python `str` argument would arrive in Lua as a Python object, which would break
    the "no Python object in Lua" rule.
  - With UTF-8, lupa raises `UnicodeDecodeError` on a Lua string that is not valid UTF-8.
  - So every text that a program can shape passes through the Lua-side `safe_text` before it reaches
    Python: a load or run-time error message, an error value, a `give_up` reason.

**Findings:**
- **F1:** lupa 2.8 keeps a `python` table in the runtime's globals even with `register_eval=False` and
  `register_builtins=False`, and `python.none.__class__` is `NoneType`, a way out of the sandbox. Programs
  never see the globals, and the sandbox removes the table anyway. ARCHITECTURE §The runtime is corrected.
- **R1 (open risk):** C functions run without the count hook. One `string.find` with four `.-` over 200
  characters ran for 13 s with no hook call. **The owner decides before v4.1:**
  - (a) drop the pattern functions and keep a plain `find`;
  - (b) run each program in a worker process with a wall-clock limit;
  - (c) cap the subject's length for the pattern functions.

  The options are recorded in ARCHITECTURE §Open decisions.
