# v2.5 — Issues

Issues for phase **v2.5 — The swap prototype: `memory` outside the program** (version **v2 — Prototype:
a text game screen, Lua runs, programs on the screen and the program swap**), derived from the
Tasks and DoD in [ROADMAP.md](../ROADMAP.md) §v2.5 and the contracts in [ARCHITECTURE.md](../ARCHITECTURE.md).
This file covers one phase; ids continue from the previous phase (GOLEM-026 → **GOLEM-027…034**).

The phase proves the swap design before v3 and v4 build on it. A second program, loaded mid-level into
the same runtime, takes over the current world with the `memory` the first program built. The step and
instruction counters carry over, and the report names the program versions that drove the run.

It builds on the v2.3 driver and sandbox and the v2.4 frames. It leaves the stops, the snapshot and the
interactive swap to v4.2, and the journal's version numbers to v5.2.

**Reconciled with the code (2026-11-21):**
- **`memory` already belongs to the run.** It is a local of the sandbox's set-up chunk, and every
  environment that `load_program` builds points to that one table. So a swap needs no new mechanism for
  `memory`, only a second `load` in the same runtime.
- **The instruction counter, the sentinel and the coroutine are upvalues of the `DRIVER` chunk.** Executing
  the chunk again would start a new counter, so the swap must live in the same closure as `step`.
- **`coroutine.close` works in lupa 2.8 / Lua 5.4.** After it the status is `dead`, and a resume answers
  `cannot resume dead coroutine` (checked with lupa while reconciling).
- **Ground truth for the report:** `golem/interp/report.py` has `REPORT_KEYS = (level, status, reason, steps,
  instructions, error)`. The report reaches `golem-local`, the server's program route (v2.4) and the tests.
  `versions` is added after `error`, so v4.1 can insert `last_actions` and `final_map` before it, as the
  contract's full report orders them.
- **No phase before this one left a finding homed to v2.5.**

**Added at the owner's request (2026-11-21, during the owner test):** the swap on the text page,
GOLEM-032…034. The owner chose to add it to v2.5 rather than to a new phase, and chose a swap in one
run: both programs are chosen before Run, as with `golem-local --swap`. An interactive swap at a pause
needs a run kept open between requests, which is the stops of v4.2.

## v2.5 — The swap prototype: `memory` outside the program

### GOLEM-027 — The run object and the swap: one runtime, a new coroutine, the counters carried over

**Description:**
A new module, `golem/interp/run.py`, holds a run: the sandbox's runtime, the world, the instruction
counter, the versions loaded and the driver's functions. `swap(run, source)` starts a new program in the
same run.

`golem/interp/driver.py` keeps the `DRIVER` chunk and `_apply`. Its `run_program` and `run_with_frames`
become thin wrappers over a run, with unchanged results.

**What needs to be done:**
- **The driver chunk returns a second function**, beside `step`: one that takes a new chunk and installs it.
  It shares the counter, the sentinel and the hook function with `step`, and:
  - closes the old coroutine with `coroutine.close`, so that it can never be resumed again;
  - creates the new coroutine from the new chunk;
  - installs the count hook on the new coroutine (`debug.sethook(co, hook, "", every)`);
  - keeps the counter, so the instruction count carries over.
- **`Run`** (in `run.py`) is created for one level, one budget, the interpreter settings and an optional
  `on_move` callback (the v2.4 frames). It holds:
  - the `Sandbox`;
  - the current `World`;
  - the instruction count;
  - the list of versions loaded;
  - the driver's two functions.
- **Starting and driving a run:**
  - `run.start(source)` loads version 1;
  - `run.drive()` resumes the program until it ends, and returns the `Ending`, as `_drive` does now.
- **`swap(run, source)`** loads the new text with `Sandbox.load`, so it gets a new environment that points
  to the same `memory`. It hands the chunk to the driver's second function and records the next version
  number. The world and the step count carry over, and the level never restarts.
- **When a swap is allowed:**
  - while the world is still playing and the program has stopped on `give_up`, on its return (`program
    ended`) or on a Lua error;
  - not after the core ended the level (solved, or lost on steps, deadlock or instructions);
  - not after `internal` or `not enough memory`.

  A refused swap raises `SwapRefused`, and the run is unchanged.
- **A swapped-in program that does not load** ends the run as `failed`/`error` with its load message, as
  at the start of a run.
- **Every failure stays a report entry:** a driver exception becomes `internal`, and the memory cap becomes
  `not enough memory`, whether before or after a swap.
- **A test-only way to show that the old coroutine is dead.** For example, the driver chunk keeps the
  retired coroutines in an upvalue and offers a function that resumes one and returns the result.
  Nothing of it is reachable from the program's environment.
- **`run_program` and `run_with_frames` are built on `Run`**, with byte-identical results for the existing
  fixtures and examples. The `on_move` frames continue across a swap.

**Dependencies:** None

**Expected result:**
A run can take a second program mid-level: the same world, the same `memory`, the counters carried over,
and the old coroutine dead.

**Acceptance criteria:**
- [ ] `swap` loads the new program into the same runtime. A value that the first program put into `memory`
  is read by the second one.
- [ ] Steps and instructions continue from the swap point. A first program that makes `k` moves and a
  second that makes `m` give a run of `k + m` steps, and the instruction count never goes back.
- [ ] The old coroutine is dead after a swap: resuming it answers `cannot resume dead coroutine`.
- [ ] The count hook is active after a swap. An infinite loop swapped in ends `lost`/`instructions`, and a
  first program that has spent most of the budget leaves the second program only the rest.
- [ ] A swap after `solved` or `lost`, or after `internal` or `not enough memory`, raises `SwapRefused` and
  changes nothing. A swap after `give_up`, a return or a Lua error is accepted.
- [ ] A swapped-in program with a syntax error ends the run `failed`/`error` with its `program:<line>:`
  message.
- [ ] The program cannot reach the driver's swap function, the retired coroutines, `coroutine` or `debug`
  through its environment.
- [ ] **Tests:** `tests/test_run.py`, with real lupa and small inline programs for:
  - the shared `memory`;
  - the counters carried over;
  - the dead coroutine;
  - the hook after a swap;
  - the refusals;
  - the load error after a swap;
  - the sandbox check.

  `tests/test_driver.py` and `tests/test_programs.py` still pass unchanged.
- [ ] **Determinism:** a swapped run, run twice, gives byte-identical reports and frames.
- [ ] **Gates:** `uv run ruff check .` clean; `uv run pytest` green.

### GOLEM-030 — `golem-local run … --swap <program.lua>`

**Description:**
`golem/local.py` gains `--swap`, so the owner can try a swap before the stops of v4.2. When the first program
gives up or returns, the second one takes over the same run.

**What needs to be done:**
- **The option:** `golem-local run <level> <program.lua> [--swap <program.lua>]`.
- **Reading the files:** both files are read and decoded before anything runs. A missing or non-UTF-8
  `--swap` file is refused with exit 1 and `{"error": "bad_program", "detail": …}` naming that file, as the
  first file is.
- **When the swap happens:**
  - if the first program ends `failed`/`give_up` (a `give_up`, or a return as `program ended`), the second
    program is swapped in and the run continues;
  - any other ending (solved, lost, a Lua error, internal, memory) ends the run there, with `versions`
    `[1]`, and the second program is never loaded.

  A swap on a Lua error belongs to the `error` stop of v4.2, not to this flag.
- **The output:** the final report, as one JSON line. The exit codes stay 0/1/2.
- **The docs:**
  - ARCHITECTURE §Components (the local runner) gains `--swap` (v2.5), with when it swaps;
  - README's `golem-local` example gains the swap command;
  - CLAUDE.md's command line already lists `--swap`, so its example is checked and kept in step.

**Dependencies:** GOLEM-028, GOLEM-029

**Expected result:**
`uv run golem-local run training/tier1/t1-01 tests/fixtures/programs/explore.lua --swap
tests/fixtures/programs/finish.lua` prints a `solved` report with `versions` `[1, 2]`.

**Acceptance criteria:**
- [ ] The DoD command reports `solved` with `versions` `[1, 2]`, and the same holds on t1-02 and t1-03.
- [ ] A first program that solves the level, loses it or fails on an error ends the run with `versions`
  `[1]`, even when the `--swap` file has a syntax error.
- [ ] `infinite_loop.lua` swapped in after `explore.lua` ends `lost`/`instructions`, and the runner
  survives.
- [ ] A missing or non-UTF-8 `--swap` file is refused with exit 1 before anything runs. Without `--swap`,
  the output is unchanged apart from `versions` `[1]`.
- [ ] **Tests:** `tests/test_local.py`, in-process (`main([...])` with `capsys`), for each case above, and
  for the DoD command run twice with byte-identical output.
- [ ] **Determinism:** the swapped command, run twice, prints byte-identical lines.
- [ ] **Gates:** `uv run ruff check .` clean; `uv run pytest` green.

### GOLEM-032 — The swap through the program route: `swap` in the body, the frames mark the swap

**Description:**
`POST /api/programs/{name}/run` takes an optional second program, and the frames show where it took over.

The swap rule is the one `golem-local --swap` uses, so it moves into `golem/interp/run.py` and both
callers use it. Touches:
- `golem/interp/run.py`;
- `golem/local.py`;
- `golem/server/app.py`;
- ARCHITECTURE;
- the tests.

**What needs to be done:**
- **One swap rule in `run.py`.** A function swaps a second program into a run whose program ended
  `failed`/`give_up` (a `give_up`, or a return), and drives it. On any other ending it does nothing.
  `golem-local --swap` uses it, with unchanged behaviour.
- **`run_with_frames(level, budget, source, settings, swap=None)`** runs the first program, applies the
  swap rule with `swap` when it is given, and returns the report and the frames.
- **The frames** (a contract):
  - every frame gains `"version"`, the program version that was driving when the frame was taken; the
    first frame has 1;
  - a swap adds a frame at the swap point: the same `step` and `map` as the frame before it, `dir` and
    `moved` set to `null`, and the new `version`;
  - the frames are bounded by the step budget plus one, plus one for each swap.
- **The route body** is `{"level": "<training id>", "swap": "<program name>"}`:
  - `swap` absent or `null` means no swap;
  - a `swap` that names no program in the folder, an invalid name or a value that is not a string gets
    `404 not_found` ("unknown program"), and a swap program that is not UTF-8 gets `422 bad_program`;
  - both programs are read before the level is checked and before anything runs;
  - the level rules do not change: training ids only, and a hidden, unknown or odd level gets
    `404 unknown_level`.
- **The log line** for a run names the swap program when there is one.
- **ARCHITECTURE:**
  - §Execution, budgets and the report: the frames get `version` and the swap frame;
  - §HTTP API: the route's body gets `swap`, and its refusals are listed.

**Dependencies:** GOLEM-030, GOLEM-031

**Expected result:**
`POST /api/programs/explore.lua/run` with `{"level": "training/tier1/t1-01", "swap": "finish.lua"}`
returns a `solved` report with `versions` `[1, 2]`, and frames that hold a swap frame at the swap point.

**Acceptance criteria:**
- [ ] With `swap`, the route's report and frames equal `run_with_frames` with the same two programs. On
  t1-01 the run is `solved` with `versions` `[1, 2]`, and exactly one frame has `dir` `null` and
  `version` 2, at the step where `explore.lua` gave up.
- [ ] A first program that does not give up or return is never swapped, and its frames all have
  `version` 1.
- [ ] Without `swap`, the frames only gain `"version": 1`, and the report is unchanged.
- [ ] An unknown, invalid or non-string `swap` gets `404 not_found`, and a non-UTF-8 swap program gets
  `422 bad_program`, before the level is checked. Hidden and unknown levels are still refused alike, with
  no hidden text in the reply.
- [ ] `golem-local --swap` behaves as before, through the shared rule.
- [ ] **Contract:** ARCHITECTURE §Execution (frames) and §HTTP API (the route) updated. They are pinned in
  the same commit by:
  - `tests/test_server_programs.py`;
  - `tests/test_driver.py` (frames);
  - `tests/test_swap.py`.
- [ ] **Determinism:** the swapped route run twice gives byte-identical JSON.
- [ ] **Gates:** `uv run ruff check .` clean; `uv run pytest` green.
