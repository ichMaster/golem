### GOLEM-002 — The level parser and its validation

**Description:**
`golem/core/level.py`: `parse_level(text, level_id) -> Level`, implementing the character table, comments
and ragged rows of ARCHITECTURE §World and rules, with every validation error naming the line and the column.
Touches `golem/core/level.py` and `tests/test_level.py`.

**What needs to be done:**
- `Cell = tuple[int, int]`, a `(row, column)` pair, zero-based, where row 0 is the first map line after
  comments. Every later phase uses this convention.
- `Level`: a frozen dataclass with:
  - `id`;
  - `width` and `height`;
  - `walls`, `goals` and `boxes` (frozensets of cells);
  - `robot` (a cell).

  Add only what the parser needs beyond these. A `render` that reproduces ragged rows is v1.2's concern.
- `LevelError(ValueError)` with `level_id`, `line` and `column`. Both are 1-based and counted in the file's
  own lines, comments included. `str()` gives `"<level_id>:<line>:<column>: <what is wrong>"`.
- Parsing:
  - `\r` is stripped;
  - lines that start with `;` are comments;
  - leading and trailing blank lines are ignored;
  - the characters map as follows: `#` wall; space, `-` or `_` floor; `$` box; `.` goal; `*` box on a goal;
    `@` robot; `+` robot on a goal;
  - any other character is an error at its position;
  - a cell past the end of a row is outside the map.
- Validation, each failure being a `LevelError` with a position:
  - exactly one robot: a second robot is reported at its own cell, and a missing robot at the first map
    line, column 1;
  - at least one box;
  - as many goals as boxes, with both counts in the message;
  - a closed map: a flood fill from the robot over the four neighbours of every non-wall cell must never
    step outside the map. The error names the last cell inside the map from which the fill escaped.
  - Text with no map lines is an error at line 1, column 1.

**Dependencies:** GOLEM-001

**Expected result:**
Any level text either parses to an immutable `Level` or raises a `LevelError` that names its line and
column.

**Acceptance criteria:**
- [ ] `parse_level` returns the walls, goals, boxes and robot of a valid level exactly, with `*` counted as
      a box and a goal, and `+` as the robot and a goal.
- [ ] **Tests:** unit tests over plain strings cover:
  - every cell character, including `-` and `_` as floor;
  - comment lines before and between map lines, with the line numbers still right;
  - ragged rows, and CRLF line ends;
  - every validation error with its exact line and column: an unknown character, no robot, two robots, no
    boxes, more boxes than goals, more goals than boxes, an open map through a gap in the wall, an open map
    through a short row, and empty text.
- [ ] **Contract:** the level text format matches ARCHITECTURE §World and rules exactly. Where the document
      is silent, the `(row, column)` cell convention and the `LevelError` line and column rule are added to
      §World and rules in the same commit.
- [ ] **Gates:** lint and tests green; `tests/test_core_imports.py` still passes.

### GOLEM-003 — Level ids, listing, loading and the budgets schema

**Description:**
`golem/core/levels.py`: list a set's level ids and load a level by id, never using an id as a raw path. Load
the per-tier budgets from `budgets.toml`. This fixes two contracts that every later phase relies on: the id
scheme `<set>/<tier>/<name>` and the `budgets.toml` schema. Touches `golem/core/levels.py`,
`tests/test_levels.py` and `specification/ARCHITECTURE.md`.

**What needs to be done:**
- `levels_root() -> Path`: `GOLEM_LEVELS_DIR` from the environment, or `levels`. Reading `.env` with
  python-dotenv comes in v2.1. Every function below takes an optional `root`, and tests always pass one.
- `list_levels(set_name, root=None) -> list[str]`:
  - lists the ids `<set>/<tier>/<name>` of every `<root>/<set>/<tier>/<name>.txt`;
  - a tier directory is `tier<N>`;
  - the list is sorted, so the order never depends on the file system.
- `load_level(level_id, root=None) -> Level`:
  - check the id's shape first: three parts separated by `/`, each matching a short lowercase pattern such
    as `[a-z0-9][a-z0-9-]*`, with no `..`, no leading `/` and no backslash;
  - then check that the id appears in `list_levels` of its set;
  - read the file that the listing found, and parse it with `parse_level`;
  - an id that fails any check raises one error type (e.g. `UnknownLevel`) that names the id and not a path.
- `Budget`, a frozen dataclass with `steps` and `instructions`.
- `load_budgets(root=None) -> dict[str, Budget]`, reading `<root>/budgets.toml` with `tomllib`:
  - one table per tier (`[tier1]`, `[tier2]`, …), each with exactly `steps` and `instructions` as positive
    integers;
  - a missing key, an extra key, or a non-integer or non-positive value is an error that names the tier and
    the key.
- ARCHITECTURE.md §World and rules, the **Budgets** paragraph: add the schema with a short TOML example, and
  the id pattern, in the same commit.

**Dependencies:** GOLEM-002

**Expected result:**
Levels are listed and loaded only by validated ids, and budgets come from a schema that ARCHITECTURE.md
states and a test pins.

**Acceptance criteria:**
- [ ] A level is reachable only through an id that the listing contains. No path built from an id is opened
      before that check.
- [ ] **Tests:** unit tests on trees built in `tmp_path` (never the real `levels/hidden/`) cover:
  - the listing is sorted across tiers and names, and ignores files that aren't `.txt` and directories that
    aren't `tier<N>`;
  - loading by id;
  - refusing an unknown id, an id with `..`, an absolute id, an id with too few or too many parts, and a
    backslash;
  - a valid `budgets.toml`, and each schema error (missing key, extra key, a string, zero, a negative);
  - `levels_root()` with and without `GOLEM_LEVELS_DIR`, through `monkeypatch`.
- [ ] **Contract:** the id scheme and the `budgets.toml` schema are written into ARCHITECTURE §World and
      rules and pinned by `tests/test_levels.py`, in the same commit.
- [ ] **Gates:** lint and tests green; `tests/test_core_imports.py` still passes (`tomllib` is standard
      library).

### GOLEM-004 — The committed levels: three tier-one levels, budgets and READMEs

**Description:**
The first content: three hand-made tier-one training levels, the budgets file, and the two READMEs. Touches
`levels/training/tier1/t1-01.txt`, `t1-02.txt`, `t1-03.txt`, `levels/budgets.toml`, `levels/README.md`,
`levels/hidden/README.md` and `tests/test_committed_levels.py`.

**What needs to be done:**
- Three tier-one levels: one box and one goal in an open room, written by hand for this project (MIT, like
  the repository).
  - Each is solvable by pushes that never leave the box in a corner off a goal.
  - The three differ in shape or position, so that a program can't solve them all with one fixed move
    string.
  - Recorded solutions come in v1.3, so keep the levels small.
- `levels/budgets.toml`:
  - a table for each of `tier1`, `tier2` and `tier3` (tiers 2 and 3 get levels in v7.1);
  - step and instruction budgets on the schema of GOLEM-003;
  - a comment saying that the values are first estimates, to be tuned in v3.2 and v7.1.
- `levels/README.md`: the format (short, linking to ARCHITECTURE §World and rules), the id scheme, the
  tiers, and the source and licence of every level.
- `levels/hidden/README.md`:
  - what belongs in this directory: the owner's hidden levels, with opaque names such as
    `hidden/tier2/h-07`;
  - why nothing but this README is committed;
  - that tests use `tests/fixtures/hidden/` instead.
- `tests/test_committed_levels.py`:
  - every id in `list_levels("training")` loads;
  - every tier that has training levels has a budget;
  - the committed `budgets.toml` loads with `tier1`, `tier2` and `tier3`.

  It never lists or reads `levels/hidden/`.

**Dependencies:** GOLEM-003

**Expected result:**
`list_levels("training")` returns `training/tier1/t1-01` … `t1-03`, every one of them parses, and the budgets
file loads.

**Acceptance criteria:**
- [ ] The three levels parse. A malformed copy (made in a test, never committed) gives a `LevelError` with its
      line and column.
- [ ] `levels/README.md` records the source and licence of each of the three levels.
- [ ] `git ls-files levels/hidden` shows only `levels/hidden/README.md`.
- [ ] **Tests:** `tests/test_committed_levels.py` as above.
- [ ] **Gates:** lint and tests green locally and in CI.
