## Findings

### 1 — 🟠 No `Cache-Control` on the page and its files

**Anchor:** `golem/server/app.py` — `_install_screen_routes`.

**Failure scenario:**
- `GET /` and `GET /screen/screen.js` carry `Last-Modified` and `ETag` but no `Cache-Control`. Browsers
  then cache by heuristic: a response whose file was last changed days ago stays fresh for a fraction of
  that age, without asking again.
- Chrome's ordinary reload revalidates only the page itself and takes its scripts from that cache. So after
  `screen.js` changes (a fix at an owner test, or v3.2 replacing the drawing), the owner presses `Cmd+R` and
  still runs the old script against the new server. The page then shows a stale screen, or messages the
  server no longer expects.
- This hits exactly the owner-test loop that v3.2 and v3.3 depend on.

**Proposed fix:**
- Send `Cache-Control: no-cache` on `/` and on every `/screen/…` file. The browser then revalidates each
  time with `If-None-Match` / `If-Modified-Since`, and the server answers `304` when nothing changed, so the
  cost stays small.
- **Regression test:** both headers are present, and a revalidation with the `ETag` gets `304`.

### 2 — 🟡 Tests that wait for the state on connect can hang

**Anchor:** `tests/test_server_ws.py`:
- `test_a_new_connection_first_receives_the_current_state` (v2.1);
- `test_a_restarted_server_finds_the_game_where_it_was`;
- `test_an_ended_game_restores_with_its_status_and_reason`;
- `test_load_and_restart_overwrite_the_save`.

**Failure scenario:**
- Each of these tests calls `ws.receive_json()` right after connecting, and `TestClient` waits without a
  timeout.
- If a regression stops the server from sending the state on connect (a broken restore, for example), the
  test waits forever instead of failing. Locally the suite hangs; in CI the job runs until GitHub's
  six-hour limit.

**Proposed fix:**
- Read the state on connect through a helper that first sends a harmless bad message (`{"type": "ping"}`,
  which leaves the game as it was) and then reads two replies.
- **When the state on connect arrives:** the first reply is that state and the second is the `ping` error.
- **When it is missing:** the first reply is the error, and the assertion fails at once.

### 3 — 🟡 A second page shows a stale map

**Anchor:** `golem/server/ws.py` — the route answers only the connection that sent the message.

**Failure scenario:** the owner has two tabs open (for example, after running `scripts/start.sh` twice).
A move in tab A changes the server's game, but tab B keeps the old map until its own next key, which then
answers with the current state. Nothing is lost, but the view in B is wrong in the meantime.

**Proposed fix:**
- Send every new state to every open connection.
- This changes the WebSocket contract ("the server answers each message"), so it needs its own decision.
  **DEFER → backlog**.

### 4 — 🟡 The page can be framed by another site

**Anchor:** `golem/server/app.py` — `screen_page` and the `/screen` mount.

**Failure scenario:**
- A site open in the owner's browser can put `http://127.0.0.1:8700/` in an invisible frame.
- The framed page's own origin passes the WebSocket `Origin` check, so keys that land in the frame move the
  robot.
- The impact is the human game only: no level text, token or file is reachable.

**Proposed fix:** `X-Frame-Options: DENY` and `Content-Security-Policy: frame-ancestors 'none'`. This
belongs with the `Host` check that v5.1 already owes (v2.1 review #3). **DEFER → v5.1**.

### 5 — 🟡 Synchronous save without `fsync`

**Anchor:** `golem/server/ws.py` — `save_game`.

**Failure scenario:**
- **No `fsync`:** a power loss right after `os.replace` can leave an empty or partial file. The next start
  then restores nothing and logs "it is not JSON": the game is lost, but the server does not crash.
- **The event loop:** the write runs on the event loop. That is under a millisecond for this file and is
  harmless for one player.

**Proposed fix:** `fsync` the temporary file before the rename, or move the save to a thread if saves grow.
Not worth it for the prototype. **DEFER → backlog**.

### 6 — 🟡 The scripts read `.env` more simply than python-dotenv

**Anchor:** `scripts/_server.sh` — `env_value`.

**Failure scenario:** python-dotenv accepts forms such as `export GOLEM_PORT=8701` and `GOLEM_PORT=8701  #
note`. In those cases the server listens on 8701, but the script checks, and opens, port 8700, or a URL with
the comment in it. `start.sh` then waits 15 s and reports that the server does not answer.

**Proposed fix:** ask Python for the value (`uv run python -c` with `dotenv_values`), or document the plain
`NAME=value` form in `.env.example`. **DEFER → backlog**.

### 7 — 🟡 The `.js` content type depends on the host

**Anchor:** `golem/server/app.py` — `StaticFiles` guesses types with `mimetypes`.

**Failure scenario:**
- Python reads the system's `mime.types` files. A host whose tables map `.js` to `application/javascript`
  breaks the content-type test.
- A host whose tables map it to `text/plain` would serve the script as plain text.
- macOS and the CI image both give `text/javascript` today.

**Proposed fix:** register `.js`, `.css` and `.html` explicitly when the screen routes are installed.
**DEFER → backlog**.

## What's solid

- **No traversal:** `StaticFiles` refuses raw and percent-encoded traversal with the usual
  `{"error", "detail"}` body, and the directory is found through the package.
- **No external URL:** no file of the page references one, including the v3.2 art scripts, and a test with
  its own positive and negative cases pins this.
- **Text only:** the page draws only with `textContent`, so a level's map or an error's `detail` can never
  become markup.
- **No rules in the page:** its only tables are the key → direction map and the display strings for loss
  reasons.
- **Restore never crashes:** `restore_game` survived all 154 malformed saves. A hidden or unknown id is
  refused like `load`, and the warning never echoes the file. A restored world is checked by the core's
  `from_json` against its level.
- **Saves are pure where it matters:** `handle` stays pure, saving happens only when the game object changes,
  and the save is byte-identical for the same messages.
- **Robust scripts:**
  - they check that the pid in the pid file is still `golem-server` before stopping it;
  - they refuse a port that another process holds;
  - when the server does not start, they show only that start's output.
