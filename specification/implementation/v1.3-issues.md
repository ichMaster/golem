## v1.3 — Save, restore and replay

### GOLEM-008 — Save and restore a world, and the state key

**Description:**
`to_json(world)` and `from_json(data, level)` in `golem/core/world.py`, which save a state as plain JSON
data and restore it exactly, and `state_key(world)` for repeat detection in v4.2. Touches
`golem/core/world.py`, `tests/test_world_json.py` and `specification/ARCHITECTURE.md`.

**What needs to be done:**
- `to_json(world) -> dict` returns only JSON types, with the keys in a fixed order:
  - `level` (the id);
  - `robot` (`[row, column]`);
  - `boxes` (a list of `[row, column]`, sorted);
  - `steps` and `step_budget`;
  - `status` and `loss_reason`.

  Two equal worlds give equal output, and `json.dumps` of it is byte-identical.
- `from_json(data, level) -> World` restores the state onto the given level. Each of these is a
  `ValueError` that names the field:
  - a `level` that is not `level.id`;
  - a missing or extra key, or a wrong type;
  - a robot or box on a wall or outside the map, or two boxes in one cell;
  - a box count that differs from the level's;
  - a negative step count;
  - an unknown status, or a `loss_reason` that doesn't fit the status.
- `state_key(world)` returns a hashable value: the robot cell and the sorted box cells. Two worlds with the
  same robot and boxes have equal keys whatever their step counts; any difference in the robot or a box
  changes the key.
- ARCHITECTURE.md §World and rules: the saved world's JSON shape, with an example, and what `from_json`
  refuses.

**Dependencies:** None

**Expected result:**
Any world can be written as plain JSON and read back to an equal `World`, and `state_key` identifies a
position independent of the step count.

**Acceptance criteria:**
- [ ] `from_json(to_json(world), world.level) == world` for playing, solved and lost worlds.
- [ ] **Tests** (`tests/test_world_json.py`):
  - the round trip, including through `json.dumps` and `json.loads`;
  - the fixed key order and the sorted boxes, for boxes added in a different order;
  - every refusal of `from_json` listed above;
  - `state_key` equality across different step counts, and inequality when the robot or one box differs.
- [ ] **Contract:** the saved world's JSON shape is written into ARCHITECTURE §World and rules and pinned by
      `tests/test_world_json.py`, in the same commit.
- [ ] **Gates:** lint and tests green; `tests/test_core_imports.py` still passes.

### GOLEM-009 — Replay a move string

**Description:**
`golem/core/replay.py`: apply a move string such as `"NNESW"` and return the final world and every state on
the way. Touches `golem/core/replay.py`, `tests/test_replay.py` and `specification/ARCHITECTURE.md`.

**What needs to be done:**
- `play(world, moves) -> (World, list[World])` applies each character of `moves` with `move`.
  - The list holds the starting world first and then the world after each move, so it has
    `len(moves) + 1` entries.
  - A character other than `N`, `E`, `S` or `W` is a `ValueError` naming its position, raised before any
    move is applied.
  - Moves after the level ends are applied as `move` applies them: nothing changes and no step is counted.
- `replay(level, moves, budget) -> (World, list[World])` is `play(new_world(level, budget), moves)`.
- ARCHITECTURE.md §World and rules: the interface line becomes `replay(level, moves, budget)` with
  `play(world, moves)`, and states the meaning of the list.

**Dependencies:** None

**Expected result:**
A move string replays to the same final world and the same list of states every time.

**Acceptance criteria:**
- [ ] **Tests** (`tests/test_replay.py`):
  - a replay that solves a level, with the expected number of states and steps;
  - the empty string (one state, the start);
  - an invalid character at a known position, with no state applied;
  - moves after the end, which add states equal to the final one;
  - `play` continuing from a world in the middle of a level.
- [ ] **Contract:** the `replay` signature in ARCHITECTURE §World and rules is updated in the same commit,
      pinned by `tests/test_replay.py`.
- [ ] **Gates:** lint and tests green; `tests/test_core_imports.py` still passes.

### GOLEM-010 — Recorded solutions and the determinism tests

**Description:**
A recorded solution for every committed training level, and the tests that carry the phase DoD: every
solution replays to `solved` twice with identical JSON, and saving, restoring and continuing gives the same
final state as an uninterrupted run. Touches `tests/fixtures/solutions/training/tier1/t1-01.txt` …
`t1-03.txt`, `tests/test_solutions.py` and `levels/README.md`.

**What needs to be done:**
- `tests/fixtures/solutions/<level id>.txt`, e.g. `tests/fixtures/solutions/training/tier1/t1-01.txt`. The
  file format:
  - lines that start with `;` are comments;
  - the rest is the move string, and whitespace is ignored.
- Record the three solutions: `EE`, `NNWNE` and `WNWS`, as checked by hand in v1.1.
- `tests/test_solutions.py`:
  - every committed training level has a solution file, and every solution file names a committed level;
  - each solution replays to `solved` within its tier's budget. Replaying it twice gives byte-identical
    `json.dumps` of the final world and of every state;
  - save, restore and continue: for each committed level and a set of seeded random move sequences
    (`random.Random(seed)`, fixed seeds), play part of the sequence, save with `to_json`, pass it through
    `json.dumps`/`json.loads`, restore with `from_json`, and play the rest. The final world must equal the
    uninterrupted run's, by `to_json`;
  - `state_key` of the final state is the same in both replays of a solution.
- `levels/README.md`: one line saying that every training level has a recorded solution in
  `tests/fixtures/solutions/`, and that a new level needs one.

**Dependencies:** GOLEM-008, GOLEM-009

**Expected result:**
Every committed training level has a solution that always replays to the same solved state, and an
interrupted, saved and restored game ends where an uninterrupted one does.

**Acceptance criteria:**
- [ ] Each recorded solution replays to `solved`, twice, with identical JSON (the concept's phase-1 "done
      when").
- [ ] Saving, restoring and continuing gives the same final state as playing the same moves without
      interruption, over at least 20 seeded random sequences per committed level.
- [ ] **Tests:** `tests/test_solutions.py` as above. The random sequences come from fixed seeds; no clock and
      no unseeded randomness.
- [ ] **Gates:** lint and tests green locally and in CI.
