# v2.4 — Issues

Issues for phase **v2.4 — Programs on the text screen** (version **v2 — Prototype: a text game screen, Lua
runs, programs on the screen and the program swap**), derived from the Tasks and DoD in
[ROADMAP.md](../ROADMAP.md) §v2.4 and the contracts in [ARCHITECTURE.md](../ARCHITECTURE.md). This file
covers one phase; ids continue from the previous phase (GOLEM-021 → **GOLEM-022…026**).

The phase lets the owner run Lua programs from a `programs/` folder on the text page:
- the driver records the world after each `move`;
- the server lists the programs, serves their code, and runs one on a training level;
- the page shows the code and plays the robot's moves back step by step, ending with the report.

The phase was added by the owner on 2026-11-20, and the swap prototype moved to v2.5. The designed screen
(v3), replays from the journal (v5.3) and the `golem` CLI (v5.1) are later.

**Reconciled with the code (v2.3.0, then 5f06d23):**
- **`golem/interp/driver.py`:**
  - `run_program(level, budget, source, settings) -> dict` returns the short report;
  - `_drive(step, world) -> (Ending, World, int)` loops over the driver chunk's replies;
  - `_apply` calls `golem.core.world.move`, `look`, `here` and `boxes_left`;
  - a `move` that ends the level stops the run before the program is resumed.
- **`golem/interp/report.py`:** `short_report`, `Ending` and `ERROR_TEXT_MAX = 500` (v2.3 review #2).
- **`golem/server/app.py`:**
  - `create_app(settings)` installs the error handlers, `GET /api/levels`, the screen routes (`GET /` and
    `/screen/…` through `_ScreenFiles`, with `Cache-Control: no-cache`) and `/ws`;
  - every error is `{"error", "detail"}`.
- **`golem/server/config.py`:** `Settings(host, port, levels_dir, log_dir, game_file=None)`, which the tests
  build positionally. A new field needs a default.
- **`golem/screen/`:**
  - `index.html` has an inline `<style>`;
  - `screen.js` has `RETRY_DELAYS_MS`, `KEY_DIRECTIONS`, `LOSS_REASONS`, `view`, `connect`, `onKey`,
    `statusText`, `drawState`, `loadLevels` and `levelGroups`;
  - `onKey` listens on `document` and acts on every arrow key, even when a form control has the focus.
- **The solver:** `tests/fixtures/programs/t1_solver.lua` solves t1-01, t1-02 and t1-03. The fixture
  programs stay as test fixtures; `programs/` gets its own copies.
- **Notes from v2.3:**
  - the spike note: lupa runtimes are per run, and Python passes in only strings, numbers and booleans;
  - spike R1: C functions run without the count hook, so a pathological program in `programs/` could hold
    a server worker thread. The owner decides R1 before v4.1;
  - v2.3 review #5 (a UTF-8 BOM) was deferred to the program readers. The new catalog reads with
    `utf-8-sig` from the start.
- **Tests:**
  - `tests/test_english_only.py` scans `golem`, `tests`, `specification`, `scripts`, `levels/training` and
    `.claude/skills`; `programs/` is added to it;
  - `tests/test_roadmap.py` checks the roadmap against `VERSION`.

## v2.4 — Programs on the text screen

### GOLEM-022 — The driver records the moves: frames from the core

**Description:**
A run can return, with its report, the world after every `move`, rendered by the core. The server sends these
maps to the page. Touches `golem/interp/driver.py`, `tests/test_driver.py` and `specification/ARCHITECTURE.md`.

**What needs to be done:**
- **`run_with_frames(level, budget, source, settings) -> (report, frames)`**, next to `run_program`, which
  keeps its signature and its report.
- **The frames:**
  - the first frame is `{"step": 0, "dir": null, "moved": null, "map": render(start)}`;
  - then one frame per `move` command, after it is applied: `{"step": world.steps, "dir": "N"|"E"|"S"|"W",
    "moved": true|false, "map": render(world)}`;
  - `look`, `here` and `boxes_left` add no frame, because they change nothing on the map;
  - a run that fails before its first move (a syntax error, for example) has only the first frame.
- **Plain data:** the frames are plain lists and dicts with fixed keys, built through a callback that
  `_drive` calls after each `move`. `_drive` stays the one loop for both functions.
- **The count:** the frames are bounded by the step budget, because every `move` costs a step.
- **ARCHITECTURE §Execution, budgets and the report:** one paragraph on the frames, their shape and that the
  maps come from the core.

**Dependencies:** None

**Expected result:**
`run_with_frames` on `t1-01` with `move("E") move("E")` gives a `solved` report and three frames whose maps
are the core's start, after `E` and after `EE`.

**Acceptance criteria:**
- [ ] **Tests** (`tests/test_driver.py`, real lupa):
  - the frames of the recorded solutions of t1-01, t1-02 and t1-03 equal `render` of the core's `replay`
    states, one per move;
  - a bump into a wall gives a frame with `moved: false` and the same map, with the step counted;
  - `look`, `here` and `boxes_left` add no frame;
  - a syntax error gives the first frame only;
  - the report from `run_with_frames` equals `run_program`'s for the same program.
- [ ] **Determinism:** `json.dumps` of `(report, frames)` is byte-identical over two runs, for every program
      in the tests.
- [ ] **Contract:** the frame shape is written in ARCHITECTURE §Execution and pinned by the tests above.
- [ ] **Gates:** lint and tests green.

### GOLEM-023 — The `programs/` folder, its catalog and the example programs

**Description:**
`programs/` at the repository root holds hand-written example programs. `golem/server/programs.py` lists and
reads them by name, never by path. Touches `programs/*.lua`, `golem/server/programs.py`,
`golem/server/config.py`, `.env.example`, `tests/test_programs.py`, `tests/test_server_app.py` (the
`.env.example` names), `tests/test_english_only.py` (scan `programs/`) and `specification/ARCHITECTURE.md`.

**What needs to be done:**
- **The examples** in `programs/`, each starting with a `--` comment line that is its description:
  - `t1_solver.lua`: the general tier-one solver (from the fixture);
  - `explorer.lua`: explores the room without pushing, then gives up with the map it saw as text rows;
  - `lost_on_steps.lua`: bumps a wall until the step budget runs out;
  - `lost_on_deadlock.lua`: pushes the box into a corner. It is written for t1-01, and its description says
    so;
  - `endless_loop.lua`: loops with no robot command and is lost on instructions;
  - `gives_up.lua`: looks around and gives up with what it saw;
  - `runtime_error.lua`: calls a nil value on a known line.
- **The catalog** (`golem/server/programs.py`), pure functions over a directory:
  - `list_programs(folder)`: `[{"name", "description", "size"}]`, sorted by name.
    - Only `*.lua` files directly in the folder whose name matches `[a-z0-9][a-z0-9_-]*\.lua` (at most 64
      characters) are listed.
    - A missing folder lists nothing.
  - `read_program(folder, name)`: the source. Anything else raises `UnknownProgram`:
    - a name that does not match the pattern;
    - a file whose resolved path is not directly inside the resolved folder (a symlink out of it);
    - a missing file.

    The file is read as `utf-8-sig`, so a BOM is dropped. Text that is not UTF-8 raises `BadProgram`.
  - The description is the first line when it starts with `--`, without the dashes and the surrounding
    spaces, and cut to 120 characters; otherwise it is empty.
- **The setting:** `Settings.programs_dir: Path | None = None`. `load_settings` resolves `GOLEM_PROGRAMS_DIR`
  (default `programs`) against the working directory. Add it to `.env.example` and its pinning test.
- **ARCHITECTURE:** the variable in §Configuration, `programs/` in §Data and state files and in the
  repository layout.

**Dependencies:** GOLEM-022

**Expected result:**
`list_programs(Path("programs"))` lists the seven examples with their descriptions, and every one of them
runs to a report on every tier-one level.

**Acceptance criteria:**
- [ ] **Tests** (`tests/test_programs.py`):
  - the listing is sorted; names that do not match, subfolders and other suffixes are left out; a missing
    folder lists nothing;
  - `read_program` refuses `../x.lua`, `/etc/x.lua`, `x.txt`, `X.lua`, an empty name and a symlink that
    points out of the folder, all with `UnknownProgram`;
  - a BOM is dropped, and bytes that are not UTF-8 give `BadProgram`;
  - every program in `programs/` runs on t1-01, t1-02 and t1-03 through `run_with_frames` and ends in a
    report;
  - `t1_solver.lua` solves all three;
  - on t1-01 the demonstrations end as their names say: lost on steps, on deadlock and on instructions,
    `give_up`, and `error` with its line;
  - every description is set.
- [ ] **Determinism:** each example program's `(report, frames)` is byte-identical over two runs.
- [ ] **Contract:** `GOLEM_PROGRAMS_DIR` is in `.env.example` and ARCHITECTURE §Configuration, pinned by
      the `.env.example` test.
- [ ] **Gates:** lint and tests green.

### GOLEM-024 — The program routes: list, source and run

**Description:**
Three routes let the page list the programs, read one, and run one on a training level. Touches
`golem/server/app.py` (or a new `golem/server/programs_routes.py` installed by `create_app`),
`tests/test_server_programs.py` and `specification/ARCHITECTURE.md`.

**What needs to be done:**
- **`GET /api/programs`:** `{"programs": [{"name", "description", "size"}]}` from `list_programs`.
- **`GET /api/programs/{name}`:** `{"name", "source"}`.
  - An unknown or invalid name gets `404 {"error": "not_found", "detail": "unknown program"}`.
  - A program that is not UTF-8 gets `422 {"error": "bad_program", …}`.
- **`POST /api/programs/{name}/run`,** with the body `{"level": "<id>"}`:
  - **The level:** only ids in `list_levels("training")`. A hidden id, an unknown id, a missing `level` and
    one that is not a string all get the same `404 {"error": "unknown_level", "detail": "unknown level"}`.
  - **The answer:** `{"report": <the short report>, "frames": [...]}` from `run_with_frames`, with the
    level's budget from `budgets.toml` and the interpreter settings from the server's environment
    (`load_interp_settings`).
  - **Off the event loop:** a plain `def` route, so FastAPI runs it in its thread pool and the WebSocket
    game stays responsive.
  - **Logging:** each run is logged with the program name, the level, and the status with its reason.
- **ARCHITECTURE:**
  - §HTTP API, "Routes outside the CLI": the three routes, their bodies and their errors. They serve the
    owner's screen, and the `golem` CLI has no command for them;
  - the Security table: program files are read by name from one folder only.

**Dependencies:** GOLEM-023

**Expected result:**
`curl -s -X POST localhost:8700/api/programs/t1_solver.lua/run -d '{"level": "training/tier1/t1-02"}'`
returns a solved report and its frames.

**Acceptance criteria:**
- [ ] **Tests** (`tests/test_server_programs.py`, `TestClient`, the programs folder in `tmp_path`):
  - the list, the source and a run that solves t1-01, whose frames equal the driver's;
  - the 404 set for names: unknown, `..%2fx.lua`, `%2e%2e%2fpyproject.toml`, `x.txt`, a symlink out of the
    folder. None returns another file's text;
  - the 404 set for levels, all with the identical body: a hidden id from the fixture hidden root, an
    unknown id, a missing level, a non-string level. No line of the fixture hidden map appears in any
    response;
  - a program that is not UTF-8 gives 422;
  - two identical runs give byte-identical JSON;
  - a program edited between two requests is served in its new form, with no restart.
- [ ] **Determinism:** the run route's JSON is byte-identical for the same program and level.
- [ ] **Contract:** the three routes, their shapes and errors are in ARCHITECTURE §HTTP API and pinned by
      `tests/test_server_programs.py`.
- [ ] **Gates:** lint and tests green.
- [ ] **Claude's check:** with `golem-server` running, the routes answer through `curl` as above.

### GOLEM-025 — The programs panel on the text page: code, Run and the playback

**Description:**
A "Programs" section on the text page lists the programs, shows the selected one's code with line numbers,
runs it on a chosen training level, and plays the frames back on its own map. Touches
`golem/screen/index.html`, `golem/screen/screen.js`, `tests/test_server_screen.py` and
`specification/ARCHITECTURE.md` (§The game screen, the text page paragraph).

**What needs to be done:**
- **The list:** one button per program from `GET /api/programs`, labelled with its name and description.
  It is fetched when the page opens, and again after a reconnect if it failed.
- **The code:** choosing a program fetches `GET /api/programs/{name}` and shows the source in a `<pre>` with
  right-aligned line numbers, so an error's `program:<line>:` can be found.
- **The run:**
  - a `<select>` of the training levels, from the same `GET /api/levels`, set to the human game's current
    level when there is one;
  - a Run button, which posts to `/api/programs/{name}/run` and disables itself until the answer arrives;
  - an error answer is shown in the panel's own error line.
- **The playback:**
  - its own map `<pre>`, separate from the human game's board;
  - one frame every 150 ms, with a line `step N · move E` (or `bump E` when `moved` is false);
  - a "Skip to end" button;
  - a new Run cancels a playback that is still going.
- **The report:** at the end, the report's status worded as on the human game ("solved in N steps", "lost —
  out of steps", "lost — a box is stuck in a corner", "lost — out of instructions", "gave up: …", "error:
  …"), with the steps and instructions.
- **Keys:** the human game's keys ignore events whose target is a form control (`SELECT`, `INPUT`,
  `TEXTAREA`), so that the arrows inside the level `<select>` never move the robot. The panel adds no game
  keys of its own.
- **Rules and URLs:** the page still holds no rules (every map comes from a frame) and has no external URL.

**Dependencies:** GOLEM-024

**Expected result:**
On `http://127.0.0.1:8700/` the owner picks `t1_solver.lua`, reads its code, picks t1-02, presses Run, and
watches the robot solve the level move by move, ending with "solved in N steps".

**Acceptance criteria:**
- [ ] The panel shows every element listed above, with the 150 ms playback, the skip, and the report
      wording.
- [ ] **Tests** (`tests/test_server_screen.py`):
  - the page still loads only `/screen/` files;
  - `screen.js` fetches only `/api/levels` and `/api/programs` paths, and still sends only the `load`,
    `move` and `restart` messages;
  - the playback interval constant is 150;
  - the arrow-key handler skips form controls (a regex pin on the target check);
  - the no-external-URL test still passes.
- [ ] **Gates:** lint and tests green.
- [ ] **Claude's check:** `node --check` on `screen.js`, plus a throwaway node harness with a fake DOM and
      `fetch` (not committed) that lists the programs, shows numbered code, runs one, plays its frames and
      prints the report line.
