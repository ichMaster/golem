Golem release notes
===================

Version 2.4.0 (2026-11-21)
---------------------------
- v2.4 (GOLEM-022..026), programs on the text screen; added at the owner's request, and the swap
  prototype moved to v2.5.
- The driver records the moves: run_with_frames gives the report and the frames, the map before the
  first move and after every move, rendered by the core.
- programs/ holds seven example programs: t1_solver.lua solves all three tier-one levels, explorer.lua
  maps the room, and one demonstration of each ending (steps, deadlock, instructions, give_up, an error
  with its line). GOLEM_PROGRAMS_DIR sets the folder.
- The program routes: GET /api/programs, GET /api/programs/{name} and POST /api/programs/{name}/run.
  Programs are read by name only, from the folder only; runs take training levels only and run off the
  event loop.
- The text page's Programs panel: the list with descriptions, the code with line numbers, a level select,
  Run, and the playback every 150 ms with a skip to the end and the report. The arrows in the select never
  move the robot.
- Code review: one run and one playback at a time on the page; README covers the programs panel, and a
  test keeps its status line in step with VERSION.
- Still open for the owner before v4.1: C functions run without the count hook (spike R1), which now also
  reaches a server worker thread through a program in programs/.

Version 2.3.0 (2026-11-20)
---------------------------
- v2.3 (GOLEM-018..021): the lupa spike (GO; lupa 2.8 with lupa.lua54 pinned): Python-driven coroutines,
  per-coroutine count hooks with a sentinel compared in Lua, max_memory, and every determinism problem
  reproduced and removed by its planned fix.
- The minimal sandbox: one runtime per run with lupa's python table and the unneeded globals removed; a
  fresh environment with the robot API (move, look, here, boxes_left, give_up), memory and the
  deterministic v2.3 subset; text-only loading; text cleaned to valid UTF-8 before it reaches Python.
- The driver and the short report (level, status, reason, steps, instructions, error): step and
  instruction budgets, give_up cut to 200 characters, errors with their line and cut to 500 characters,
  the memory cap, and internal failures, each ending in one report.
- uv run golem-local run <level> <program.lua>, and fixture programs; t1_solver.lua solves all three
  tier-one levels.
- The repository is English only (CLAUDE.md, with a guard test); the roadmap's release marks are checked
  against VERSION.
- Open decision for the owner before v4.1: C functions such as the pattern matcher run without the count
  hook (spike R1).

Version 2.2.0 (2026-11-20)
---------------------------
- v2.2 (GOLEM-014..017): GET / and /screen/... serve the game screen from the package; raw and encoded
  traversal get 404, and no page file references an external URL.
- The text game page: the map in a <pre>, steps / budget, the status with its reason, level buttons from
  /api/levels, arrows to move and R to restart; it reconnects after 0.5, 1, 2, 4 s, then every 5 s.
- The human game survives a server restart: saved atomically to data/human-game.json after every change
  and restored at start (training levels only; a bad save is ignored with a warning).
- Owner test: scripts/start.sh, stop.sh and restart.sh run golem-server in the background; a person's name
  removed from a design-system comment. The owner confirmed the three manual DoD checks.
- Code review: the page files are sent with Cache-Control: no-cache; tests that wait for the state on
  connect fail fast instead of hanging.
- Specification: the "Clay and stone" design brief and handoff; v2 is now the prototype (v2.2 text screen,
  v2.3 Lua runs, v2.4 swap), v3 the designed screen, v4 the interpreter; two sandbox design holes closed
  (string.format addresses, the string metatable).

Version 2.1.0 (2026-11-19)
---------------------------
- v2.1 (GOLEM-011..013): golem-server (FastAPI + uvicorn) on loopback only; settings from the environment
  and .env; start-up checks of the levels directory and budgets; rotating data/logs/server.log;
  {"error", "detail"} for every HTTP error.
- GET /api/levels: the training levels with tier, size and budgets; hidden levels are never listed.
- WebSocket /ws: the human game through the core (load, move, restart -> state); errors keep the
  connection open; hidden, unknown and non-string ids get the same "unknown level"; the current state is
  sent on connect.
- Code review: /ws accepts only the server's own page; .env is read from the working directory only.
- Owner test: hands-on testing of the human game moved to v2.2 at the owner's request.

Version 1.3.0 (2026-11-19)
---------------------------
- v1.1 (GOLEM-001..004): uv project with ruff and pytest gates and GitHub Actions CI; Sokoban level parser
  with line/column errors; level ids, listing and loading by id; per-tier budgets in levels/budgets.toml;
  three tier-one training levels.
- v1.2 (GOLEM-005..007): immutable World with moves, one-box pushes, one step per move, the step budget,
  the corner rule and the win; look, here, boxes_left and render.
- v1.3 (GOLEM-008..010): save and restore a world as JSON, state_key, replay of move strings; recorded
  solutions replay to solved twice with identical JSON.
- Code review: a restored world keeps the robot and boxes inside the walls; levels with unreachable boxes
  or goals are refused; documentation drift fixed.
